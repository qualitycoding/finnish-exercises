# Decisions (D-###), interfaces and decision rules

## Architecture and interfaces

**D-001 Static site, no build.** Plain HTML, CSS and ES modules served as-is by GitHub Pages from `main`, folder `/`. Files: `index.html`, `assets/app.js`, `assets/scoring.js`, `assets/style.css`, `data/manifest.json`, `data/themes/<id>.json`, `.nojekyll`. Reference implementation: `qualitycoding/swedish-exercises` at `b8c4f57` (Apache-2.0, same owner), which may be copied and adapted. *Rejected:* a bundler or framework (adds a build step that Pages would need an Actions deploy for).

**D-002 Theme data format.** As `qualitycoding/skills` `skills/learning-exercise-site/references/theme-schema.md`, with these Finnish changes:
- Exercise keys: `luku` (reading), `kuuntelu` (listening), `kirjoitus` (writing), `puhe` (speaking). Display names: *Luetun ymmärtäminen* (Reading), *Kuullun ymmärtäminen* (Listening), *Kirjoittaminen* (Writing), *Puhuminen* (Speaking).
- Theme fields: `id` (`<ascii-slug>-<yyyymmdd>`, the content research date), `title`, `short`, `dateLabel` (Finnish, e.g. `7. marraskuuta 2026`), `level` (`B1–B2`), `summary`, `sources` (`[{title, url}]`, https, ≥2 distinct hosts), `exercises`.
- `luku`: `title`, `intro`, `text` (paragraphs, standard Finnish), `dialogue` (paragraphs; the first starts with `(keksitty esimerkki)`), `questions` (10: `mc`/`tf`).
- `kuuntelu`: `title`, `intro`, `vocab`, `script` (standard Finnish), `dialogue` (spoken Finnish, first paragraph starts `(keksitty esimerkki)`), `questions` (exactly 8 `mc`/`tf` + 2 `dictation`).
- `kirjoitus`: `title`, `tasks` (exactly 4 `gap`, 3 `order`, 3 `translate`), `free` (`prompt`, `words`, `checklist`, `model`).
- `puhe`: `title`, `tasks` (exactly 6 `read`, 4 `respond`).
- Markup `[[shown|gloss|label]]`, label ∈ `slangi`, `puhekieli`, `idiomi`, empty; gloss = Finnish explanation, ` · `, English.
- Word count = whitespace-separated tokens of `plain()` text that contain at least one letter.

**D-003 Validator interface.** `tools/validate.mjs` exports `GENERIC_SENTENCES` (string array, includes `"Se on totta."`), `validateTheme(theme, file) → string[]` and `validateAll(root) → {problems, summary}`; run as a CLI (`node tools/validate.mjs [root]`) it exits 0 only if `validateAll` finds no problem. Every problem string contains its rule id in brackets. Rules:
V1 required fields, dated ascii id, unique id, file name `themes/<id>.json`; V2 ≥2 https sources on distinct hosts (`www.` ignored); V3 10 items and the exact item-type mix of D-002; V4 markup well-formed, known label, gloss contains ` · `; V5 reading 200–450 words, ≥1 `slangi` and ≥1 `puhekieli` term, dialogue starts `(keksitty esimerkki)`; V6 listening (script + dialogue) 120–320 words, dialogue has ≥1 `puhekieli` term and starts `(keksitty esimerkki)`; V7 mc ≥3 distinct options and answer in range, tf boolean; V8 gap has `___` and its first accepted answer scores 1, and each theme's writing has at least one gap whose first accepted answer contains ä or ö (T-035 uses the newest theme); V9 order: no commas, 3–8 chips, canonical rebuilds, alternatives use the same words, and the reversed canonical sequence is not an accepted order (so the deliberately wrong run of T-031 stays ≤ 2); V10 translate/respond: non-empty stems, the model hits every group, and every `GENERIC_SENTENCES` entry scores 0; V11 no digits in dictation or read-aloud targets; V12 free writing has all fields. A working implementation exists at `research/spikes/satisfiability/validate.mjs` (passes T-010…T-024).

**D-004 Scoring rules (frozen as T-001…T-009).** `assets/scoring.js` exports `normalize, fold, tokens, levenshtein, wordSimilarity, scoreTyped, scoreOrder, scoreKeywords, scoreSimilarity, total, shuffle, parseMarkup, plain` with the behaviour of the reference implementation and these Finnish changes: `fold` maps ä→a, ö→o, å→a; the ½-point note for an ä/ö slip names ä and ö; feedback notes in English; **keyword stems of one or two letters match whole words only** (so `ei` does not match *eilen*; found by spike `research/spikes/scoring-finnish`). Thresholds: gap exact → 1, ä/ö-only or one edit in a word of 6+ letters → ½; order exact listed sequence → 1; keywords all → 1, ≥ half → ½; dictation/read-aloud word similarity ≥ 0.9 → 1, ≥ 0.7 → ½; speaking best of 3 attempts; self-assessment 0/½/1. Rationale for no typo allowance under 6 letters: Finnish vowel and consonant length is phonemic (*tuli/tuuli*, *kuka/kukka*).

**D-005 Word-order tasks in Finnish.** Finnish word order is freer than Swedish. Each `order` task is built around a fixed-order construction (question clitic *-ko/-kö* first, negative verb before the main verb, postposition after its noun, adjective before noun, auxiliary *olla* before participle) and lists **every** grammatical order of its chips in `accept`; ≤8 chips (V9). If the learner trial reports a correct order marked wrong, the order is added to `accept` and a T-test is added (G-LEARN rule).

**D-006 UI contract (frozen as T-030…T-047).** Hash routes `#/`, `#/harjoitus/<themeId>/<kind>`, `#/tietoja`. `html[data-ready]` = `1` after data loads, `error` on load failure with `#load-error` naming URL, HTTP status and content type; `html[data-route]` = current hash after each render. Index: `a[data-ex='<themeId>-<kind>']` with `.badge.done` text `10/10` when best is 10; `#total-best` text starting with the summed best and ` /`; `a#continue` to the first exercise below full marks; `.legend` with `.tag.slangi`, `.tag.puhekieli`, `.tag.idiomi`, `.tag.sana`. Exercise page: `.legend` (4 tags), `.news-date` containing `dateLabel`, `.sources a[href^='https://']`, items `#app .q` in data order; mc/tf `label.option[data-correct='1'|'0']` (options reshuffled per attempt with a new seed); gap/dictation `input`; translate `textarea`; order chips `.chips:not(.built) .chip`; speaking `button.rec`, `.transcript[data-heard]` after a result; self-assessment radios `input[value='0'|'0.5'|'1']` when recognition is absent; `#check`, `#score[data-score]`, `#retry` (clears score); `.feedback[data-points]`; `a[data-nav='prev'|'next']` following manifest order × skill order; reading page: `article` contains the text **and** the dialogue (so `article .term .tag.slangi` and the words 'keksitty esimerkki' are inside it) and `.news-date`/`.sources` sit on every exercise page; terms `article .term` with `.tag.<label>` and a `.pop` explanation that opens on tap and closes on second tap, tap elsewhere or Escape (one open). Listening: `#play` speaks script then dialogue sentence by sentence with `lang = 'fi-FI'`, markup stripped; `#voice-status[data-voice='fi'|'none']`. Speaking: recognition `lang = 'fi-FI'`, `maxAlternatives = 3`. About: `#export` (download JSON), `input#import` with `#import-status[data-ok='1'|'0']` (a bad file leaves scores untouched). Storage failure shows `#save-error`. Use a DOM helper that flattens arrays and drops `null` (L-20261102T230300Z).

**D-007 Voice selection.** Normalise each voice's `lang` (lower case, `_`→`-`). Rank: (1) `fi-fi` and name matches `/Natural|Online/`; (2) `fi-fi`; (3) lang starts with `fi`. Take the first voice of the best non-empty rank. If `getVoices()` already returns voices, use them at once (no waiting). Wait for `voiceschanged` up to 2 s. If none: `data-voice='none'` and the message "No Finnish voice found. Install a Finnish text-to-speech voice in your device settings, or use Microsoft Edge, Safari or Chrome on Android. You can still read the transcript." Facts: K-20261107T001000Z-finnish-tts-voices (Chrome desktop ships no Finnish voice; Apple *Satu*, Windows *Heidi*, Android/ChromeOS *Google Suomi*, Edge *Noora/Harri* online).

**D-006a Test-derived UI details (from `tests/e2e.test.mjs`; the test file is authoritative).**
1. `#app .q` count equals the item count (10): free writing, vocab and dialogue blocks never use class `q`.
2. Each `.q` contains exactly one answer control (`input`, `textarea` or `button.rec`), except mc/tf (labels) and self-assessment (radios).
3. `.feedback[data-points]` sits inside its `.q`; values `0`, `0.5`, `1`. `#score[data-score]` holds the total as a number string (`10`, `9.5`).
4. Order chips: one `.chip` per token of `accept[0]` (sentence-initial capital kept, final `.?!` removed), duplicate words get separate chips; a used chip gets the `disabled` attribute.
5. `#score` is removed from the DOM by `#retry` (count 0), not hidden.
6. `a[data-nav='next']` is absent on the last exercise, `a[data-nav='prev']` absent on the first.
7. The reading page has one `<article>` (text + dialogue) and an `h1`.
8. Exactly one `a[data-ex='<id>-<kind>']` per exercise on the index; `a#continue` has no `data-ex`.
9. Index `.legend .tag.<label>` count 1 each; exercise pages `.legend .tag` count 4.
10. `html[data-route]` is the full hash (`#/`, `#/harjoitus/<id>/<kind>`, `#/tietoja`).
11. `#load-error` text: `${path}: HTTP ${status}, ${contentType}` (e.g. `data/manifest.json: HTTP 404, text/html`).
12. `#play` queues every sentence synchronously (no `onend` chaining, no wait when voices exist), each utterance `lang = 'fi-FI'`; script first, then dialogue.
13. Use only `speechSynthesis.getVoices/speak/cancel/addEventListener('voiceschanged', …)`.
14. Recognition: assign `onresult`, `onend`, `onerror` as properties; read `event.results[0][i].transcript` for `i < length`; set `lang` before `start()`.
15. No console errors on any page: include `<link rel="icon" href="data:,">`.
16. The app loads and works when `Storage.prototype.setItem` throws; `#save-error` appears after `#check`.
17. `h1` visible and tappable at 412 px width.
18. Without recognition: zero `button.rec`; each speaking `.q` has radios `value='0'`, `'0.5'`, `'1'`.

**D-008 Persistence.** `localStorage` key `suomi-harjoitukset:v1`, value `{version:1, scores:{'<themeId>-<kind>':{best,last,attempts,history:[{score,at}]}}, drafts:{}}`; every access in try/catch; history capped at 20. Import accepts only an object with `version === 1` and a `scores` object; otherwise `data-ok='0'` and nothing changes.

**D-009 Content currency and integrity.** Content is researched on the day it is written (S-006). Each theme has a content note `content-notes/<id>.md` listing every fact used in a question or model answer with two independent sources (distinct publishers; L-20261009T123005Z) and every sentence naming a real person with its source. Nothing is quoted beyond 15 words; texts are original. Political themes give each side's stated position in paraphrase.

**D-010 Branching and publication.** Implementation on `impl-20261106T235415Z-finnish-current-affairs-exercises` (from the generation branch). `S-PUBLISH` merges it into `main` with `git merge --no-ff` and pushes; `main` is the Pages source. Plan, research and review files are part of the public repository (A-011; no secrets, Rule 13).

**D-011 Tooling.** Node 22 (`actions/setup-node` `node-version: "22"`); Playwright `1.63.0` (npm, verified to exist; sandbox has browsers at `/opt/pw-browsers`, Chromium 153 launched in spike `research/spikes/playwright-launch.mjs`). Tests run with `node --test tests/*.test.mjs` (the directory form `node --test tests/` fails on Node 22: observed in the satisfiability spike).

**D-012 CI platform matrix.** Supported learner platforms are browsers, not build hosts: iOS Safari, Android Chrome, desktop Chrome/Edge/Safari/Firefox. CI runs the whole suite in headless Chromium on `ubuntu-24.04` (pinned label). WebKit and Firefox e2e jobs are waived (`D-012`): the sandbox has only Chromium preinstalled, the app uses no engine-specific API apart from Web Speech (which the tests replace with a fake), and the real-device check is G-LEARN question 3. ARM64, libc-variant and oldest-toolchain jobs: N/A (no native code; Node 22 is the only toolchain).

**D-013 No generated audio.** Speech is produced by the learner's browser. `audio = false`; 3.10 N/A.

**D-014 Mutation testing opt-out.** `S-MUTATE` is omitted: the scored logic is one small pure module (`scoring.js`, ~180 lines) whose rules are each pinned by an exact-value unit test, and every validator rule now has a test that must fail on a broken fixture (T-011…T-023, T-052…T-058; the gap found in round 1, R-031, is closed by D-017), which is the property mutation testing would measure. Cost (Stryker install and ~10–20 min per run) outweighs the gain for a hobby site.

**D-015 Phone screenshots.** `tools/screenshots.mjs` renders the index, a reading page with an open `slangi` explanation, a writing page and a speaking page in Playwright `devices['Pixel 7']` to `docs/screenshots/*.png`; the implementer opens each with the Read tool and records what it saw in `EXECUTION_LOG.md`.

**D-016 Refresh.** `REFRESH.md` adapted from `qualitycoding/swedish-exercises/REFRESH.md` (b8c4f57) to Finnish (sources, keys, labels, dialogue rule, date format), and `.github/workflows/live-check.yml` adapted with `SITE: https://qualitycoding.github.io/finnish-exercises/`. Schedule per A-017, created only after G-LEARN `proceed` (3.11 item 8).

**D-017 Amendment after pre-mortem round 1 (Phase 2 re-run).** New frozen tests `tests/scoring-v2.test.mjs` (T-025, T-027, T-029), `tests/validate-v2.test.mjs` (T-051…T-058) and `tests/e2e-v2.test.mjs` (T-048…T-050, T-059); red-verified against the stubs (`research/spikes/red-v2-*.txt`), satisfiable against the spike (35/35 unit and validator tests). The original frozen files are unchanged. Changes:
- *Scoring (R-009, R-010, R-011, R-023).* `scoreTyped(input, accepted, near = [])`: a listed near-miss scores 0 before the typo rule. Keyword stems of 4+ letters match anywhere inside a word (compounds); 3-letter stems at word start; 1–2-letter stems whole words. New `scoreSpoken(alternatives, target)`: character similarity with spaces removed, best alternative, ≥ 0.9 → 1, ≥ 0.6 → ½; used for read-aloud; `respond` items use `scoreKeywords` on each alternative and keep the best. 'Best of 3' = up to three recording taps per item, the best tap counts, `#retry` resets it. Dictation (typed) keeps `scoreSimilarity`.
- *Validator.* `validateTheme` adds V14 (optional `variants` on translate/respond, each must score 1), V15 (no Finnish number words in read-aloud/dictation targets), V16 (no `<` or `>` anywhere in a theme); V9 now allows 3–6 chips. New export `contentRules(theme, file)` with V13 (every gap has a `near` list of ≥1 typical wrong forms, none of them accepted); `validateAll` and the CLI run `validateTheme` + `contentRules` and V17 (`content-notes/<id>.md` exists). Content guidance: give `respond` items `variants` for natural short answers (e.g. *Budjetin.*) only when they hit every keyword group; otherwise phrase the question so a full sentence is asked for ('Vastaa kokonaisella lauseella').
- *Word order (R-012; supersedes the 'every grammatical order' part of D-005).* The task instruction says 'Build the sentence in neutral word order (subject – verb – object/adverbial)'. `accept` lists the neutral order and, if needed, other neutral variants; the reversed sequence must not be accepted (V9). Each content note says in one line why the reversed order is not neutral.
- *Security (R-014).* No `innerHTML`, `outerHTML`, `insertAdjacentHTML` or `document.write` in `assets/*.js` (CI step 'No HTML injection sinks'); `index.html` carries `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'">`.
- *Import (R-013, supersedes the import part of D-008).* Reject files > 1 MB. Parse with `JSON.parse`; require `version === 1` and an object `scores`. Build a fresh object with `Object.create(null)` semantics (copy only own keys); accept only keys matching `^[a-z0-9]+(-[a-z0-9]+)*-\d{8}-(luku|kuuntelu|kirjoitus|puhe)$`; each entry needs numeric `best`, `last` in 0–10 in steps of 0.5, integer `attempts` ≥ 0, array `history`; merge per key: `best = max`, `attempts = max`, `last` from the entry with the newer last history time, `history` = union by `at`, newest 20. Invalid entries are skipped and counted in `#import-status`. Never `Object.assign` imported data onto the store.
- *Persistence on iOS (R-019).* Call `navigator.storage?.persist?.()` once at start-up (best effort, with a 2 s timeout, errors ignored but logged with `console.warn`, never `console.error`). The About page explains that Safari may delete site data after 7 days without a visit unless the site is added to the Home Screen, and the index shows 'Back up your scores' linking to `#/tietoja` when the last export (stored as `lastExport`) is older than 7 days and any score exists.
- *Speech (R-020, R-027).* `#play` is never disabled; every tap re-runs voice selection (D-007) and speaks with `lang = 'fi-FI'` even when no Finnish voice was found (the browser may still find one). The `(keksitty esimerkki)` marker is displayed but stripped before speaking; sentences are not split after an ordinal (`\d\.`) or the abbreviations `esim.`, `mm.`, `n.`, `ns.`, `ts.`, `jne.`.
- *Publishers (R-016, supersedes the publisher definition in PLAN S-006 step 0).* Publisher groups: Yle (Yle Uutiset, Yle Selkouutiset, Svenska Yle); Sanoma (HS, IS); Alma Media (Iltalehti, Kauppalehti, Talouselämä); MTV (MTV Uutiset); STT (wire, counted once wherever it appears); Government (valtioneuvosto.fi, ministries, agencies — one group per authority). Two independent sources = two different groups.
- *Slang fallback (R-017).* If Kielitoimiston sanakirja is unreachable at S-000, use only slang words that appear as slang in two independent sources found by search (record both URLs in the content note); never label a word `slangi` on recall alone.
- *Relative time (R-026).* Texts use absolute dates ('7. marraskuuta'), never *eilen*/*tällä viikolla* about the news.
- *Live check acceptance (R-018).* A `Live site check` run counts only if its job `live` concluded `success` (`gh api repos/qualitycoding/finnish-exercises/actions/runs/<id>/jobs --jq '.jobs[]|[.name,.conclusion]|@tsv'`). If none appears within 10 minutes of a successful Pages build, start one with `gh workflow run live-check.yml --ref main` and use that run.
- *Refresh flow (R-015, supersedes the publish part of D-016).* A refresh run commits to branch `refresh/<id>`, pushes it, waits for `CI` success on that commit (CI triggers include `refresh/**` and a step fails if any existing `data/themes/*.json` on `origin/main` was modified or deleted), then fast-forwards `main` (`git push origin refresh/<id>:main`, never `--force`) and confirms the three runs for the commit. Each refresh adds `content-notes/<id>.md` (V17).
- *Taxonomy (A-020).* At S-KNOW, add the new tags (`domain:finnish-current-affairs`, `tech:web-speech-api`, `tech:github-pages`, and the knowledge `subject:` tags) to each store's `TAXONOMY.md` in the same commit.
- *Accepted Medium risks.* R-021 (growth: revisit when the manifest exceeds 12 themes), R-022 (refresh stall: the task notifies the owner), R-024 (slang regional note in the gloss), R-025 (About wording 'may have no Finnish voice'), R-028 (no WebKit CI; G-LEARN on the owner's phone), R-029, R-030.

## Decision rules (if → then)

| ID | If | Then |
|---|---|---|
| R-D1 | `npm ci` fails in CI | Regenerate the lockfile in a clean directory (`mkdir /tmp/lock && cp package.json /tmp/lock && cd /tmp/lock && npm install --package-lock-only`), copy it back, log in `DEVIATIONS.md`, retry once; still failing → `BLOCKED.md`. |
| R-D2 | A frozen test fails and the implementer believes the test is wrong | Halt that step, write `TEST_CHALLENGE.md` (test id, evidence, proposed fix); continue only steps that do not depend on it. Never edit a frozen file. |
| R-D3 | The validator rejects a theme | Fix the theme content, never the validator rule; three attempts per theme, then drop that theme, pick another topic area, and log it. |
| R-D4 | No second independent source for a fact | Remove the fact from questions and model answers (it may stay in context text only if it is attributed to its source in the sentence). |
| R-D5 | A sentence about a named real person has no source | Delete it or move the content into the invented dialogue with no real names. |
| R-D6 | A news page cannot be fetched (paywall, 403) | Use another outlet; never circumvent a paywall; record the source as `unreachable` in the register. |
| R-D7 | CI fails on the pushed commit | Read the failing step through `gh api repos/qualitycoding/finnish-exercises/actions/runs/<id>/jobs` and the check-run annotations; fix and push; three attempts, then `BLOCKED.md`. |
| R-D8 | The first `pages build and deployment` run ends `startup_failure` | Re-run it once (`gh api -X POST repos/qualitycoding/finnish-exercises/actions/runs/<id>/rerun`) or push an empty commit; still failing → report at G-LEARN as blocked hosting. |
| R-D9 | Live-site check fails (a data file not served as JSON) | Inspect the annotation; if Pages serves a stale 404, re-run after 5 minutes once; else fix paths and redeploy. |
| R-D10 | A review (S-REVIEW / S-ADVERSARIAL) finds a Critical or High issue | Fix before S-PUBLISH; new tests go through Phase 2 (unfreeze, add, red-verify, re-freeze) with a `D-###` amendment. |
| R-D11 | `npm audit --omit=dev` reports a vulnerability | There are no runtime dependencies; dev-only (Playwright) advisories are recorded in `reviews/CODE_REVIEW.md` and fixed by a patch-level bump logged in `DEVIATIONS.md`. |
| R-D12 | Default rule | Choose the most reversible option that does not expand scope, log it in `DEVIATIONS.md` with rationale, and continue — **unless** it touches frozen tests, security, data integrity, a public interface, or research integrity, in which case halt and write `BLOCKED.md`. |
